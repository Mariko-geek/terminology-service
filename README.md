# Сервис терминологии

Тестовое задание: небольшой сервис версионируемых справочников на Django + SQLite.

## Что реализовано

- модели Справочник → Версия → Элемент;
- ограничения уникальности из задания;
- русскоязычная Django Admin;
- редактирование версий внутри справочника и элементов внутри версии;
- `GET /refbooks/` и фильтр `?date=ГГГГ-ММ-ДД`;
- `GET /refbooks/<id>/elements` с выбором текущей версии;
- `GET /refbooks/<id>/check_element`;
- Swagger;
- тесты API и ограничений модели.

## Запуск

```bash
python -m venv .venv
```

Windows:

```bash
.venv\Scripts\activate
```

Linux/macOS:

```bash
source .venv/bin/activate
```

Далее:

```bash
pip install -r requirements.txt
```

```bash
python manage.py migrate
```

```bash
python manage.py createsuperuser
```

```bash
python manage.py load_demo_data
```

```bash
python manage.py runserver
```

После запуска:

- админка: `http://127.0.0.1:8000/admin/`
- Swagger: `http://127.0.0.1:8000/api/schema/swagger-ui/`

## Как проверить API


### Проверка через Swagger

Список справочников:
```http
GET /refbooks/
```

Справочники, у которых к указанной дате уже существует вступившая в действие версия:
```http
GET /refbooks/?date=2026-07-15
```

Важно: по заданию этот метод возвращает список справочников, а не номер версии. 
Условие означает: у справочника должна существовать хотя бы одна версия с `start_date <= date`.

Элементы явно выбранной версии:
```http
GET /refbooks/1/elements?version=10.4
```
Если `version` не передана, сервис выбирает текущую версию: версию с самой поздней `start_date`, которая не позже сегодняшней даты.

Проверка пары «код + значение»:
```http
GET /refbooks/1/check_element?code=100&value=Врач-стоматолог&version=10.5
```
Ответ:
```json
{"valid": true}
```
Формат ответа `check_element` в исходном задании отдельно не задан, поэтому используется простой ответ `{"valid": boolean}`.

## Демонстрационные данные

Команда `load_demo_data` создаёт два небольших примера:

1. `1.2.643.5.1.13.13.11.1002` — должности медицинских работников, версии `10.3`, `10.4`, `10.5`.
2. `1.2.643.5.1.13.13.11.1005` — демонстрационный фрагмент МКБ-10, версии `2.25`, `2.26`, `2.27`.

Во втором примере версии действительно отличаются: в `2.26` появляется `Z01.6`, а в `2.27` добавлены `Z00.2` и `Z01.7`. Даты начала действия в demo-наборе условные и нужны только для демонстрации логики задания; они не выдаются за официальные даты публикации/вступления версий НСИ в силу.
